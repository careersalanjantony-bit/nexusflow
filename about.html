How I got here

I graduated in Computer Science & Engineering in 2024 and joined Bobcares in Kochi that August as a junior software engineer on web hosting and server support. Two years on I handle L2/L3 escalations across shared, VPS and dedicated Linux servers for a global managed-hosting client base.

Support is a useful place to learn, because it teaches you the difference between a fix that makes the alert go away and a fix that makes the problem go away. The tickets that reach me have usually already defeated someone else, so guessing isn't an option — you read the logs, attribute the load, and prove what happened.

The work splits three ways. Escalations and incidents: high-load events on production nodes, mail and DNS failures, compromise investigation and cleanup. Recovery: InnoDB corruption, disk-full damage, data rebuilt from pre-rebuild snapshots. Planned change: PHP and platform upgrades, cPanel-to-cPanel and DigitalOcean-to-AWS migrations with tested rollback paths.

I'm currently extending into DevOps and cloud — AWS Cloud Practitioner and Solutions Architect Associate are both in progress, with GCP after that.

How I work

  • Read before you touch. Logs, monitoring history and change records come before any command that modifies state.
  • Backup before you break. No destructive operation goes ahead without a verified, restorable copy — and I've tested the restore, not just the backup job.
  • Rollback plan first. The maintenance window doesn't open until the "how do we undo this" step is written down.
  • Least privilege by default. Root is a last resort, not a starting point. Same for open ports and firewall exceptions.
  • Write it down. Every non-trivial incident ends in an RCA the customer can actually read. Undocumented fixes come back.
  • Automate the second time. Do it manually once to understand it, then script it so it's consistent forever.
