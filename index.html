About me

The engineer they call when the ticket has already been escalated twice.

I'm a Linux server administrator working the managed-hosting side of infrastructure — the place where a single misconfigured php-fpm pool, an expired certificate or a compromised WordPress plugin turns into a customer outage within minutes.

Most of my day is spent on L2 and L3 escalations: reproducing the fault, reading the logs properly instead of guessing, applying a fix that holds, and writing the RCA so the same ticket doesn't come back next month. The rest is planned work — security hardening, incident response and server migrations that customers shouldn't be able to feel.

I care about two things above all: not losing data, and not surprising the customer. Every migration gets a rollback plan before it gets a start time. Every hardening change gets tested where it can't take a live site down. That discipline is why I can put numbers like the ones above on a page.
